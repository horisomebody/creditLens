# Home Credit 스파이크 결과 — 1·2단계

> 1단계 노트북: `ml/notebooks/spike_home_credit_stage1.ipynb` (2026-09-17 실행, 189.6초, 에러 없음) — 주 테이블 단독
> 2단계 노트북: `ml/notebooks/spike_home_credit_stage2.ipynb` (2026-09-17 실행, 247.3초, 에러 없음) — 보조 테이블 조인 추가
> 전처리는 GMC 스파이크와 동일한 원칙(결측 중앙값 대체, 알려진 코드값 처리, 극단값 클리핑)에 범주형 원-핫 인코딩을 더한 가안이다.
> 정식 Phase 5(결측 플래그, 인코딩 전략 재설계 등)를 대체하지 않는다.

## 결론

**연구 질문의 증거가 쌓이고 있다: 데이터가 복잡해질수록(변수만 늘어나도, 다중 테이블을 조인해도) XGBoost 우위가 계속 커진다.**

| 지표 | GMC (변수 10개) | HC 1단계 (주 테이블만, 변수 121개) | HC 2단계 (다중 테이블 조인, 변수 147개) |
|---|---|---|---|
| 로지스틱 회귀 AUC | 0.8598 | 0.7487 | 0.7636 |
| XGBoost AUC | 0.8691 | 0.7613 | 0.7767 |
| AUC 격차(XGB-LR) | +0.0093 | +0.0126 | **+0.0131** |
| 상위 5% 정밀도 — 로지스틱 | 47.47% | 31.31% | 33.16% |
| 상위 5% 정밀도 — XGBoost | 48.00% | 34.40% | 37.00% |
| 상위 5% 정밀도 격차 | +0.5%p | +3.1%p | **+3.8%p** |
| 상위 5% 포착률 격차 | +0.4%p | +1.9%p | **+2.4%p** |

격차가 GMC → HC 1단계 → HC 2단계로 갈수록 **단조 증가**한다(AUC +0.0093 → +0.0126 → +0.0131,
상위 5% 정밀도 +0.5%p → +3.1%p → +3.8%p). 다중 테이블 조인이 절대 성능(AUC, 정밀도)도 둘 다 끌어올렸지만,
XGBoost가 조인 피처로부터 더 많은 이득을 봐서 로지스틱 회귀와의 격차 자체도 더 벌어졌다.
GMC에서 "사실상 동률"이었던 비교가 다중 테이블 조인까지 더해지자 뚜렷한 XGBoost 우위로 바뀌었다.

## 0. 1단계·2단계 차이

- **1단계**: `application_train.csv` 단독. 121피처(원-핫 후 234개).
- **2단계**: 1단계에 보조 테이블 5종을 대출자(`SK_ID_CURR`) 단위로 집계해 조인 — 121 + 26개 신규 피처(원-핫 후 260개).
  집계는 신용 위험과 직결되는 핵심 지표로 한정한 최소 구현이다(완전 탐색 아님):
  - `bureau`+`bureau_balance`: 신용조회 건수, 활성 건수, 총 신용/채무액, 연체일수 최댓값, 월별 연체 상태 비율
  - `previous_application`: 과거 신청 건수, 승인율/거절율, 평균 신청·승인 금액
  - `POS_CASH_balance`: 건수, 연체일수(SK_DPD) 평균/최댓값
  - `credit_card_balance`: 건수, 잔액 평균/최댓값, 연체일수 최댓값, **한도 대비 사용률**(GMC의 `RevolvingUtilization`과 동일한 개념)
  - `installments_payments`: 상환 건수, 평균 연체일수, 연체 비율, 상환/청구 비율

## 1. 데이터 구조

- 307,511행 × 121피처(타깃 제외). 수치형 104개, 범주형 16개(GMC는 전부 수치형 10개).
- 타깃 양성 비율 8.07% (GMC 6.68%와 비슷한 정도의 불균형).
- 결측률 50% 이상 컬럼 41개(주로 건물/아파트 관련 `_AVG`, `_MODE`, `_MEDI` 계열). 결측이 전혀 없는 컬럼은 54개.

## 2. 알려진 이상값: `DAYS_EMPLOYED`의 365243 코드값

GMC의 연체 변수 96/98 코드값과 같은 패턴이 확인됐다 — 특정 값이 "해당 없음"(주로 무직/연금생활자로 추정)을
나타내는 placeholder로 쓰였다.

- 365243 값 55,374건(18.0%).
- 이 값을 가진 행의 타깃 양성 비율 5.40% — 전체 평균(8.07%)보다 낮음. 즉 "무직/연금생활자 placeholder" 그룹이
  오히려 저위험군에 가깝다는 신호로, 단순 결측 처리보다 별도 플래그로 다루는 게 나을 수 있다(Phase 5에서 결정).

## 3. 최소 전처리

- `DAYS_EMPLOYED` 365243 → 결측 처리
- 수치형 결측 → 중앙값 대체
- 범주형 결측 → "Missing" 범주로 채운 뒤 원-핫 인코딩(`drop_first=True`)
- 원-핫 인코딩으로 피처 수 121 → 234개로 증가
- 수치형 전체 0.5%~99.5% 분위수로 winsorize

## 4. 모델 비교

5-fold 대신 **3-fold CV**로 탐색 속도를 조정했다(데이터 규모가 GMC보다 훨씬 크기 때문). 홀드아웃은 동일하게 20%.

- 로지스틱 회귀 탐색 57.3초, 최적 `C=0.01`, `class_weight=balanced`
- XGBoost 탐색 130.1초, 최적 `scale_pos_weight=5`(불균형 비율 11.39 전체를 쓰는 것보다 낮은 값이 선택됨 —
  GMC에서 `scale_pos_weight=1`이 최적이었던 것과 다른 방향. 데이터마다 최적값이 다르다는 근거)

두 모델의 절대 AUC(0.75~0.76)는 GMC(0.86~0.87)보다 낮다. 이는 모델의 한계라기보다, 아직 `bureau`·
`previous_application` 등 신용 이력을 담은 보조 테이블을 조인하지 않았기 때문일 가능성이 크다
(Kaggle 공개 벤치마크에서도 `application_train` 단독으로는 보통 AUC 0.74~0.76대, 전체 테이블을 다 쓰면
0.78~0.80대로 올라간다).

## 6. 2단계 — 다중 테이블 조인 결과

### 조인 후 결측 패턴

신규 피처의 결측은 "해당 보조 테이블에 기록 자체가 없는 대출자"를 뜻한다 — 결측률이 곧 의미 있는 정보다.

| 피처 그룹 | 결측률 | 해석 |
|---|---|---|
| `CC_*`(신용카드) | 71.7~72.0% | 신용카드 이력이 없는 대출자가 대다수(72%) |
| `BUREAU_BALANCE_DPD_RATIO_MEAN` | 70.0% | 타 금융기관 신용조회 중 월별 이력이 있는 경우가 적음 |
| `BUREAU_*` | 14.3% | 타 금융기관 신용조회 이력이 없는 대출자 14% |
| `POS_*` | 5.9% | POS/현금 대출 이력 없음 |
| `PREV_*`, `INSTALL_*` | 5.1~5.4% | Home Credit 내 과거 대출 이력 없음(첫 거래 고객으로 추정) |

정식 Phase 5에서는 이 결측을 단순 중앙값 대체 대신 "이력 없음" 플래그로 명시적으로 남기는 방안을 검토해야 한다
(중앙값 대체는 "이력이 없다"는 정보 자체를 지워버린다).

### 모델 비교

- 로지스틱 회귀 탐색 62.3초, 최적 `C=0.1`, `class_weight=balanced` (1단계의 `C=0.01`과 다름 — 피처가 늘며 최적 정규화 강도도 바뀜)
- XGBoost 탐색 146.9초, 최적 파라미터가 1단계와 거의 동일(`scale_pos_weight=5` 등) — 조인 피처가 늘어도 트리 구조 자체의
  최적 복잡도는 크게 안 바뀐 것으로 보인다.
- 두 모델 다 절대 성능이 올랐다(로지스틱 AUC 0.7487→0.7636, XGBoost AUC 0.7613→0.7767) — 조인 피처가 실제로
  유효한 신호를 추가했다는 뜻이다.

### XGBoost 피처 중요도 상위 15개 — 신규 조인 피처 3개 진입

| 순위 | 변수 | 중요도 | 비고 |
|---|---|---|---|
| 1 | `EXT_SOURCE_2` | 0.0773 | 블랙박스 |
| 2 | `EXT_SOURCE_3` | 0.0681 | 블랙박스 |
| 3 | `NAME_EDUCATION_TYPE_Higher education` | 0.0461 | |
| 4 | `INSTALL_LATE_RATIO` | 0.0272 | **신규(조인)** — 과거 상환 연체 비율 |
| ... | | | |
| 8 | `PREV_REFUSED_RATIO` | 0.0204 | **신규(조인)** — 과거 신청 거절율 |
| 10 | `CC_UTILIZATION_MEAN` | 0.0188 | **신규(조인)** — 신용카드 한도 사용률 |

`EXT_SOURCE_2/3`는 여전히 1·2위로 블랙박스 우려가 그대로 남아 있다. 다만 **신규 조인 피처 3개(연체 비율, 과거 거절율,
카드 사용률)가 상위 15개 안에 들었다** — 전부 "왜 위험한지"를 사람이 이해할 수 있는 직관적인 변수라, SHAP 사유 코드로
바꾸기 좋은 후보들이다. 즉 다중 테이블 조인이 성능만 올린 게 아니라 **설명하기 쉬운 피처를 추가로 공급**했다는 점도
Phase 7에서 긍정적으로 쓸 수 있다.

## 7. 3단계 — `EXT_SOURCE_1/2/3` 제외 (운영 가능성 검증)

> 실행 노트북: `ml/notebooks/spike_home_credit_stage3.ipynb` (2026-09-17 실행, 260.1초, 에러 없음)

### 배경

`EXT_SOURCE_1/2/3`는 정의가 공개되지 않은 외부 신용평가 점수이며, 실제로는 Home Credit이 외부 신용평가사와
맺은 상업 계약으로 확보한 데이터다. **CreditLens가 실제 운영 시스템이 될 경우 이 계약이 없어 재현할 수 없는
피처다.** 2단계와 완전히 동일한 파이프라인(다중 테이블 조인 포함)에서 이 세 컬럼만 제외하고
"현실적으로 확보 가능한 데이터만으로" 성능이 얼마나 나오는지 확인했다.

### 결과: 성능은 떨어지지만, 격차는 좁혀지지 않았다(오히려 소폭 벌어짐)

| 지표 | HC 2단계(EXT_SOURCE 포함) | HC 3단계(EXT_SOURCE 제외) | 변화 |
|---|---|---|---|
| 로지스틱 회귀 AUC | 0.7636 | 0.7299 | **-0.0337** |
| XGBoost AUC | 0.7767 | 0.7466 | **-0.0301** |
| AUC 격차(XGB-LR) | +0.0131 | **+0.0167** | +0.0036(벌어짐) |
| 상위 5% 정밀도 격차 | +3.84%p | +3.74%p | -0.10%p(거의 유지) |
| 상위 5% 포착률 격차 | +2.38%p | +2.32%p | -0.06%p(거의 유지) |

**"현실적인 운영 가능 버전"은 두 모델 다 AUC가 약 3%p 떨어진다** — 이게 CreditLens가 실제로 감수해야 하는
성능 비용이다. 다만 애초 기대(블랙박스 변수를 빼면 XGBoost-로지스틱 격차도 GMC 수준으로 줄어들 것)와 달리,
**격차는 줄지 않고 오히려 AUC 기준으로는 더 벌어졌다.** 해석: `EXT_SOURCE`는 단일 정규화 점수라 로지스틱 회귀
같은 선형 모델이 활용하기 좋은 신호였던 것으로 보인다. 이 신호를 빼고 나니 남는 건 범주형 조합·이력 통계 같은
비선형적 관계가 많은 피처들이고, 이건 트리 모델(XGBoost)이 상대적으로 더 잘 다룬다 — 그래서 격차가 안 줄어든 것.

### 새로운 1위 변수 — 전부 설명 가능한 변수로 교체됨

| 순위 | 변수 | 중요도 |
|---|---|---|
| 1 | `NAME_EDUCATION_TYPE_Higher education` | 0.0768 |
| 2 | `REGION_RATING_CLIENT_W_CITY` | 0.0377 |
| 3 | `NAME_INCOME_TYPE_Working` | 0.0329 |
| 4 | `PREV_REFUSED_RATIO`(파생) | 0.0316 |
| 5 | `INSTALL_LATE_RATIO`(파생) | 0.0302 |
| 6 | `BUREAU_DAYS_CREDIT_MEAN`(파생) | 0.0257 |

**상위 15개 안에 블랙박스 변수가 하나도 없다.** 학력, 지역등급, 소득유형, 과거 거절율, 연체율, 신용조회 이력,
카드 사용률 — 전부 고객에게 "왜 이 사유가 나왔는지" 설명할 수 있는 변수들이다.

### 결론 — 성능과 설명 가능성의 트레이드오프가 숫자로 드러남

| 버전 | AUC(XGBoost) | 설명 가능성 |
|---|---|---|
| `EXT_SOURCE` 포함(2단계) | 0.7767 | 1·2위가 블랙박스 — 상위 사유 코드 일부를 못 씀 |
| `EXT_SOURCE` 제외(3단계, 운영 가능 버전) | 0.7466 (**-0.0301**) | 상위 15개 전부 설명 가능 |

**약 3%p의 AUC를 포기하면, 완전히 설명 가능한 모델을 얻는다.** 이건 이 프로젝트가 정확히 검증하려던
트레이드오프이고, 실제 수치로 확인됐다는 점에서 의미가 크다. Phase 7에서 최종적으로 `EXT_SOURCE` 포함/제외
버전 중 무엇을 "운영용 모델"로 쓸지는 "3%p 성능과 완전한 설명 가능성 중 무엇이 더 중요한가"라는 정책 결정이며,
CreditLens가 실제 운영 가능한 시스템(제3자 신용평가 계약 없이)을 목표로 한다면 3단계(제외) 버전이 현실적인
기본 후보가 된다.
